## 7. Bugs discovered

1. Critical: anonymous callers had broad table grants and allow-all RLS policies on business tables.
2. Medium data-quality finding: four product stock maps contain an uppercase legacy branch UUID key in addition to the canonical lowercase key.
3. Informational business-state finding: two products have negative stock. The affected branch explicitly permits negative-stock sales.
4. Advisory follow-up: Supabase reports public/signed-in `SECURITY DEFINER` functions and duplicate permissive policies that require individual intent review; the public terminal/coupon/member functions tested here enforce their narrow contracts.

## 8. Severity and impact

- Anonymous table access: critical confidentiality and integrity exposure; visitors could potentially enumerate or mutate business data.
- Case-duplicated inventory key: medium; branch stock can be split or displayed differently from the aggregate quantity.
- Negative stock: informational under the current configured rule, but it should remain visible to operations.
- Advisor findings: mixed; mostly defense-in-depth/performance warnings rather than proven exploits.

## 9. Root cause

- Legacy `GRANT ALL` statements and broad `Public access` RLS policies survived later hardening layers.
- Four legacy inventory rows used a differently cased representation of the same UUID-like branch identifier.
- Negative stock is allowed because `prevent_negative_stock_sale` is disabled for the affected branch.

## 10. Fix implemented

- Revoked anonymous privileges on all public tables and sequences.
- Restored anonymous `SELECT` only for feature flags and coupon campaigns.
- Removed legacy allow-all business-table policies and public voucher/settings/payment/barcode reads.
- Restored settings reads only for authenticated users.
- Added browser automation and regression tests that lock the access contract.
